# Сопровождение курса

Канонические слайды находятся в `public/course.json`, сценарий — в `public/teacher-notes.json`, ключи самопроверки — в `public/assessment.json`. После объединения литературы прежние ссылки перенаправляются через `slideAliases`; сохранённое место чтения также учитывает эту карту. В каждом вопросе схема механизма, изменённый разобранный случай и задача для группового разбора выполняют разные учебные задачи.

Условия задач описаны в `authoring/cases.mjs` и `authoring/cases.json`, состояния демонстраций — в `authoring/demonstrations.mjs`, схемы исходных примеров — в `authoring/explanation-boards.mjs`. Сборка состояний и паспортов: `node scripts/build-demonstrations.mjs`. После правки условий согласуйте обе модели. `scripts/validate-cases.mjs` независимо пересчитывает 160 контрольных результатов и проверяет диапазоны шкал, интервалы, структуру снимков и литературу.

В кейсах нет ввода текстового ответа и оценки попытки. Условие и задание находятся на слайде; кнопка сразу открывает рабочую модель. `workbenchModels.ts` содержит предметные операции над изменяемыми входами: отбор, пары JOIN, группы, агрегаты, расчёты с единицами, границы транзакции и проверки ограничений. `OperationWorkbench` выполняет операцию и строит результат по текущим данным. Изменение входа сбрасывает зависимые результаты; отмена возвращает согласованный снимок. Модель оповещения вычисляет состояния по часам и событиям, учитывая сброс непрерывного превышения. Это учебные вычисления в браузере, а не подключение к MySQL или Prometheus.

Группа отвечает устно. «Окно для группы» получает публичные входы, выполненную операцию, время и события; при позднем открытии восстанавливает снимок без управляющих кнопок и преподавательских заметок. Прежние `demonstrations.json` и их проверки сохраняют историю статических разборов; текущая мастерская использует исполняемые модели. Условия на слайдах и сценарии согласуются через `node scripts/upgrade-case-workbenches.mjs`; запускайте его после прежних генераторов. Проверки вычислений и изменённых входов — `tests/workbench.test.ts`. Исходные объясняющие схемы слайдов сохранены независимо от кейсов.

Изменённые условия разобранных примеров хранятся в `authoring/variations.mjs`; исходные данные схем — в `authoring/examples.mjs`. Применение вариаций: `node scripts/refine-variations.mjs`. Применение прикладных заданий: `node scripts/refine-assessment.mjs`. `scripts/refine-course.mjs` — однократная миграция прежней редакции; на текущей редакции она намеренно остановится. Не используйте отсутствующий старый приватный генератор поверх текущих данных.

Рабочий движок закреплён как локальная зависимость `engine-extension/runtime/`. Его опубликованная сборка (runtime, описание пакета и README без неиспользуемых руководств и демонстрационных ресурсов) сохранена в `vendor/olgakraven-lecture-engine-0.1.1-okfks.10-visuals.2.tgz`; адаптация воспроизводится `py -3 -B scripts/prepare-runtime.py` (Windows) или `python3 -B scripts/prepare-runtime.py` (macOS/Linux). Общий шаблон и соседние курсы не изменяются. Прежний пакет используется только серверными проверками схем данных.

Проверки: `npm ci`, `npm run lint`, `npm run typecheck`, `npm run test`, `npm run spellcheck`, `npm run validate:cases`, `npm run build`, `npm run check:privacy`. Существующий workflow GitHub Pages разворачивает `main` после этих проверок. `npm run export:pdf -- --out output/pdf` создаёт PDF из текущего печатного представления; выходные файлы в Git не включаются.

Текст и сценарий преподавателя выгружаются командой `node scripts/export-teaching.mjs <локальная папка>`. Рабочее место комплекта — хранилище BrainM. JSON-карты содержат SHA-256 точных байтов курса и реальные ID каждого слайда; учебный Markdown не содержит версий и технических отчётов. `.gitattributes` сохраняет точные байты курса и исходного пакета заметок на разных устройствах.

Прежняя автоматически загруженная запись обновляется только при совпадении с сохранённым отпечатком базового поля. Личные заметки удалённых слайдов литературы добавляются к объединённому слайду, прежний ключ хранилища остаётся нетронутым. Новые правки во время занятия сохраняются. Окно аудитории сценарий не загружает. Браузер не исполняет SQL на сервере.

Все схемы слайдов и развёрнутого просмотра используют `LearningVisual` / `ContentVisual` и общий профиль `src/learning/learning.css`. `ScenarioBoard` отвечает за таблицы, цепочки, числовые и временные шкалы; `TechnicalText` различает объяснение и технические данные. Пошаговое объяснение сохраняет полную модель и меняет только текущий фокус. Дополнения используют тот же стиль при смене предметных снимков.

Пояснения механизмов находятся в `authoring/student-explanations.mjs`, контекст и исходные понятия — в `authoring/student-lessons.mjs`, практические действия и ожидаемые результаты — в `authoring/student-practice.mjs`. Файлы практики лежат в `public/practice/`. Команда `node scripts/integrate-student-content.mjs` встраивает материал непосредственно в слайды: первый абзац в понятие, второй в продолжение перед схемой, практику перед итогом. Старые ID и записи «Запишите» сохраняются. Код разбивается без потери строк; выполняется полный скачанный файл. После запуска прежних генераторов повторно применяйте эту интеграцию, затем выгружайте согласованные тексты преподавателя.

`scripts/validate-student-content.mjs` проверяет наличие всех абзацев, действий, результатов и полного SQL в лекциях, сохранность прежних ссылок и определений. Он входит в `validate:content`. Отдельного режима чтения нет; прежние адреса `mode=read` ведут к соответствующему месту лекции. Практика описывает локальное выполнение; браузер не выполняет SQL. Оповещения проверяются в Prometheus, внешняя доставка требует отдельной настройки.

Последняя содержательная проверка — `reports/student-content-2026-10-25.md` и JSON рядом. Проверка оформления — `reports/infographic-design-2026-10-24.md`. Этап групповых задач — в `reports/group-demonstrations-2026-10-24.md`; `reports/review-2026-10-24.md` фиксирует прежний вариант с формами. Более ранние QUALITY, registry и migration-map относятся к прежнему переносу.
